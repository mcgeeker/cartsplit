# CartSplit 1.9.6 trial and 2.0 acceptance

**Current signed prerelease: [1.9.6](https://github.com/mcgeeker/cartsplit/releases/tag/v1.9.6).**
Milestones 6 and 7 have synthetic verification and initial real-page checks.
The owner reports the workflow is working well and is using 1.9.6 for a longer
trial to find bugs or improvements before finalizing 2.0.0. Continue with 1.9.x
updates as needed; use 2.0.0 when the remaining acceptance/review checks pass.

Version 1.9.3 places the CartSplit logo at the left of the Payee column and indents
the payee name so native dropdowns remain clear. It also fixes a false unconfirmed
result when YNAB returns its internal category ID labelled **Split** on a split
parent. Every approved split amount, category and memo must still match; genuine
uncertainty remains locked against retries. Version 1.9.2 fixed lookup-status
access from Firefox's extension tab. Version 1.9.1 fixed
missing controls caused by YNAB's per-row attachment file inputs. Controls appear
beside supported Amazon purchases in an individual account; the **All Accounts**
view is not supported. Reload the temporary add-on and refresh the YNAB tab after
updating a development build.

Version 1.9.4 moves lookup progress and choices into the sidebar, reuses an
existing Payments tab in the same window, and focuses the matching Order Details
tab. It recognizes Amazon's labelled pagination inputs and waits for a fresh
GET navigation before reading a reset Payments page, avoiding form-resend prompts.

Version 1.9.5 keeps line memo drafts available in collapsed **Memo for line N**
sections before price confirmation. Hover or focus an **ⓘ** control to preview
guidance; click to expand it in the sidebar, or press Escape to close it.
Starting order review hides the completed lookup panel and page count. A new
lookup shows progress again; active searches retain their controls.

Version 1.9.6 keeps the sidebar in place when review starts. Expanding memos,
settings, breakdowns and guidance scrolls only when needed to reveal content, using
the nearest edge. Long sections leave the remaining content to normal scrolling.
The general guidance icon is always beside **Purchase review** after a successful
review, including multi-product orders without separate adjustments. Icons use
drawn circles and an information mark so their appearance does not depend on a font.

## Open an order from YNAB

1. In the selected CAD plan's account register, click the **CartSplit logo** at
   the left of the Payee column on an Amazon/AMZN outflow. Its accessible label
   is **Open Amazon order**. Categorized, split and reconciled parent purchases can
   be looked up; supported accounts remain open, on-budget Cash, Checking,
   Savings and Credit Card accounts.
2. Follow progress in the **CartSplit sidebar**. If it is closed, open it using
   Firefox's sidebar controls; a short notice reminds you. Firefox prevents a
   button inside YNAB from opening a closed extension sidebar automatically.
   Lookup reuses a Payments tab in this window, starts at page one and searches
   the exact amount within two calendar days. **Cancel lookup** changes no YNAB data.
3. If Amazon requires sign-in, choose **Sign in to Amazon**, sign in locally,
   return to the sidebar and choose **Resume**. A search segment checks up to
   50 pages or runs for 120 seconds; choose **Continue** for another segment.
4. One uniquely matching order opens and becomes the selected tab after the
   complete date window is checked. An existing tab for that order is reused.
   Several matching orders appear as choices. Incomplete or unreadable history
   stops lookup; it is never reported as a verified missing/unique match.
5. Choose **Review selected order** in CartSplit's
   sidebar. Lookup restores its matching payments page and review uses that
   selected Payments tab when other Payments tabs are open. Existing save eligibility
   and ambiguity rules still apply. The completed lookup panel disappears when
   review starts.

Only English Amazon.ca card payment rows with readable card funding are supported.
Refunds and gift-card funding are excluded. Register lookup requires the new
permission for `app.ynab.com`; credentials stay in the extension background.
Live YNAB/Amazon layouts still need owner acceptance. Unsupported or ambiguous
display dates without a stable row ID are deliberately left unsupported.

## Edit memos during a category save

1. Review an eligible new purchase using the normal sidebar flow. Inspect
   **Existing transaction memo** and the editable **Transaction memo**. The
   suggestion retains existing text and appends an order number/link. A sole
   product's name and quantity are also suggested in the parent memo.
2. Expand **Memo for line N** to edit a product's memo, including before its price
   is confirmed. These sections start collapsed and preserve drafts when you
   confirm prices. Product rows stay separate even when their categories match. Whole
   quantities stay together; separately categorized shipping/fees retain their
   own lines and descriptive memos.
3. Keep every memo at or below 500 characters. The counter shows the complete
   text; overlong suggestions require editing and are never silently shortened.
   An empty field explicitly clears that memo. A payment with one resulting
   category line uses its transaction memo; product-line drafts apply to split
   payments.
4. Choose **Prepare changes** or **Prepare selected payment**. Read the complete
   parent memo, line memos, amounts, plan and account. Editing a memo revokes the
   prepared approval. Each payment has a separate transaction memo draft.
5. Approve and save once. Inspect the transaction and split memos in YNAB after
   verified success. Existing categorized/split purchases cannot receive memo-only
   edits. An unconfirmed response still requires manual inspection and no retry.

## Controlled owner acceptance

1. Create a separate Firefox profile for this development build using the
   [profile instructions](personal-installation.md#create-or-choose-a-profile).
   Keep the existing signed installation and its profile data preserved.
2. Load `apps/extension/.output/firefox-mv2/manifest.json` with **Load Temporary
   Add-on** in `about:debugging#/runtime/this-firefox`. Enter a token only in the
   local CartSplit connection screen and select the intended CAD plan.
3. Perform read-only lookup checks first: a known Amazon purchase, an older
   categorized/split/reconciled purchase, and any naturally available ambiguous
   match. Confirm the opened order, cancellation and sign-in behavior. Do not
   alter transactions to manufacture matches.
4. On a suitable new purchase, review the memo/category proposal. Each actual
   save requires the owner's deliberate final approval. Check a sole product
   and a multi-product order with repeated categories when available; preserve
   previous accepted saves. Record observed results without credentials or
   private purchase details in public files.
5. After acceptance and the [repository review](security-review-2026-10-29.md)
   gate pass, bump to 2.0.0 and prepare fresh matching release packages. Signing,
   installation and publication follow the existing release approval process.

## Draft 2.0.0 release notes

- Open matching Amazon.ca orders from supported YNAB register purchases.
- Search paginated Amazon card payments with progress, cancellation, explicit
  sign-in resume and ambiguous-order choices.
- Preview and edit transaction and product-line memos before approved saves.
- Preserve separate product lines when categories repeat, with 500-character
  validation and exact memo/line verification.
- Keep direct-to-YNAB authentication, local learning and individual save approval.
